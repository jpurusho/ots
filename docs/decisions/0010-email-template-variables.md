# 0010 — Email template variable system

**Status:** accepted
**Date:** 2026-10-30

## Context

Users need to customize email subject lines and footer text for offering reports and cards. Hard-coded values like "Generated by OTS" don't meet all church branding needs.

Requirements:
- Customizable subject and footer text
- Support dynamic values (church name, date, period, count)
- Live preview in Settings to avoid template errors
- Variables must be clearly documented

## Decision

Implement a simple `{variable}` template syntax stored in `app_settings` table:
- `email_subject_template`: defaults to `{church} — {period}`
- `email_footer_text`: defaults to `Generated by OTS`

Supported variables:
- `{church}` — church name from settings
- `{period}` — "October 2026" or "Week of 10/20/2024" or "Selected Cards (3)"
- `{date}` — offering date for single card, current date for reports
- `{generated}` — current date when report/email was generated
- `{count}` — number of cards being emailed (for multi-card emails)

Frontend resolves variables via `resolveEmailTemplate()` function. Settings page shows live preview with sample values.

## Consequences

- Email subject and footer are now fully customizable per-instance
- Churches can add branding like "Generated by CCI San Ramon - {generated}"
- Template variables are resolved at email/PDF generation time
- Invalid variable names (e.g., `{unknown}`) are left as-is in output
- Migration added default templates to existing instances
- PDF backend accepts `footer_text` parameter, no more hardcoded strings
